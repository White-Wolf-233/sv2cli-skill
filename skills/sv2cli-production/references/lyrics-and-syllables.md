# 填词、分音与连唱

## 先取得可信的对应关系

工程有声音、F0 接近写入的音高，只能说明引擎在执行数据。不能由生成脚本导出同一份数据再比对，就宣称原谱和歌词已核实。记录独立来源、版本、页/小节、声部和反复段次；缺少原谱时先诊断现有工程，标明无法确定的逐音对应，不凭歌曲印象补写和声或宣布保谱。

先将反复、跳房子和多段词展开到实际演唱顺序。相同旋律可以复用，歌词须按每一段分别指定；不要复制第一段整段歌词，再只替换几个形容词。歌词应按语义位置/音节 ID 替换，不能对全部声部共用同一拍点的两个字符替换规则：各部节奏和分词可能不同。

建立可审阅的表：段次、声部、页/小节、绝对拍点、时值、实际音高、歌词、音节 ID、新起字/续前字、原谱连线/延音、来源位置。以四分音符为一拍；从简谱读八度时查实际谱号/八度标记，不因标成 T/B 就自动降八度，也不因声部交叉就改音。

## 音节与音符不是一对一

- 汉语通常一字一音节，但一字可以唱多个音符；标点、空格和休止不是可填字的音符。不要用 `zip(汉字, 音符)`、字符数凑齐、平均切词或尾部重复最后一字来完成填词。
- 新字/新音节放在原谱对应音符。一字多音的后续音使用已验证的 SV2 continuation `-`，不能重复原字重新起声；在分声部入口也要保留此前完整音节上下文。
- 同音延音线连接同一个持续音；换音连线仍保留多个音高并续唱前字。同音换字仍须重新发字，不能因为音高相同就合并。不要把任意弧线都当成延音线。
- 重复同一个元音可能是原谱重新起声，也可能是误填。查谱和音节 ID 后再改；不要全曲一律改成 `-`，不要靠缩短时值制造断音。
- 中文歌词优先交给已核实的 Mandarin 声库/语言覆盖；多音字和不清楚的短字先做对应片段。需要音素覆盖时核对声库/语言音素集，用实际支持的 live API 读取计算音素（如当前版本可用）并检查发音，不猜 xsampa 写法、不把拼音或声调数字直接当音素。没有计算音素或听审时明确未验证。

修改歌词或音素属于改谱数据。用真实 `recipe-schema` 配方、精确选择器与 `--allow-score-changes`，对比白名单内的预期改动；不要承诺整份 score fingerprint 不变。音高、时值、速度、非目标声部等应独立保持一致。后续只改音色再启用 `--score-lock`。

## 渲染前可直接执行的核对

使用 CLI 的 `lyrics-plan-schema` 查看格式，`lyrics-check` 只读 SVP 和独立核对计划，不改工程、不合成、不调用 ASR；核心不依赖插件或第三方包。随 skill 提供的 [scripts/audit_lyrics.py](../scripts/audit_lyrics.py) 只是同一命令的转发入口，要求同一个 Python 中已安装支持该命令的 CLI；没有另一份核对实现或旧版回退。

```sh
sv2cli lyrics-plan-schema
sv2cli lyrics-check song.svp --plan lyrics-plan.json -o lyrics-audit.json
# 对完整生产计划额外要求没有任何未映射音符：
sv2cli lyrics-check song.svp --plan lyrics-plan.json --require-full-project -o full-audit.json
sv2cli render song.svp --lyrics-plan lyrics-plan.json --stems -o stems
```

计划示例（示例内容不对应任何歌曲；start/end/at/dur 均为绝对四分拍，可用分数字符串）：

```json
{
  "source": {"reference": "score.pdf pp.1-2, checked lyric underlay", "reviewed": true},
  "tracks": [{"selector": "#1", "phrases": [{
    "id": "verse-1-line-1", "start": "0", "end": "4", "text": "山河",
    "notes": [
      {"at": "0", "dur": "1", "pitch": 60, "lyrics": "山"},
      {"at": "1", "dur": "1", "pitch": 62, "lyrics": "-"},
      {"at": "2", "dur": "2", "pitch": 64, "lyrics": "河"}
    ]
  }]}]
}
```

每段要分别提供预期文本和逐音表，脚本对比实际绝对拍点/时值/音高/歌词；可在 notes 条目加 `phonemes` 核对显式覆盖。它会展开主组和库组引用及 pitchOffset/blickOffset，发现重复/缺失音、错字、错序、漏 continuation，按声部和段次报告。段落区间不能重叠，不能在持续音内部截开；特殊符号不会自动删除。默认要求逐音表，`--text-only` 仅用于初步诊断现有歌词，不能当成分音验收。

`source.reviewed` 是调用者声明，脚本不会替人看谱；它始终将原谱验证、计算音素验证和主观听审标成未独立验证。只核对若干段时会报告剩余未覆盖音符。不要从正在验收的 SVP 反向自动生成“独立计划”来证明它自身正确。

检查失败返回非零退出码，并使普通 batch 在后续渲染前停止。生产时 `render --lyrics-plan` 会在加载插件前要求计划覆盖全部可听音符、逐音一致且来源复核已声明完成；不能只改 `reviewed` 布尔值来绕过真实复核。现有可信工程只改音色、或明确的无词探针，不强制补造歌词计划。

写入时 `lyrics.set` / `phonemes.set` 的 values 是**单个声部、按绝对拍点排列**的完整音符列表，包含显式 `-`；同时起音不明确时工具拒绝，改用独立声部或带 uuid/reference 选择器的 `notes.update`。先看 dry-run 中的 `noteOrder`，再写入，不能按主组/库组的存储顺序推测演唱顺序。

## 从数据核对到实际声音

数据对应正确后，挑新字密集、同音换字、一字多音、延音、分声部入口和不同段词的代表片段，检查干声。短段预览保留真实语境及前滚，不从连音中间新起一个元音。F0 检查不能识别漏字/错字；活动窗口不能证明音素正确；ASR 只作提示，合唱及延长元音仍需对照。

每个输入/配置只合成一次，问题先定位到具体段次、声部、字及音符，再按原因修改。全曲交付分别报告：歌词逐段是否一致、逐音对应、计算音素（如有）、实际发声时序、短字和连唱检查、听审范围。未完成的检查不能合并成“全部通过”。
