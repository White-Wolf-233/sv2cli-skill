# 失败恢复与交付

先读输出旁 manifest 的 status/tasks/error，以及 `.sv2cli-jobs` 下对应日志。不得杀掉用户已打开的 Studio 或删除全局声库缓存来试错。

```sh
sv2cli render song.svp --stems -o stems --bit-depth 24 --resume
```

用同一套参数续跑；完成轨须通过文件哈希、音频和格式校验才复用。完整音色/混音/调参、CLI 版本、后端配置或导出设置改变，会拒绝复用。声库外部文件更新但工程身份不变时，显式重渲染，不依赖旧 checkpoint。旧产物缺少 checkpoint 时不能冒充可验证缓存。

分轨默认跳过空轨、静音轨和 renderEnabled=false 的轨，在 manifest.skipped 说明原因。要求这些轨也发声时，先明确修改相应状态。分轨已含轨道增益、声像和效果，混音不能重复应用。新版分轨保持原工程完整时间轴和统一帧数；历史文件仍需核对原点、采样率和时长，按同一时间轴补零后求和；有主总线效果时，不承诺分轨和等于独立 master render。

工具只输出 WAV；需要 MP3/FLAC 时检查 ffmpeg 等编码器后执行真实转换。按用户需求交付工程、混音、编号分轨及映射、练习版、同时间轴 A/B 与验收 JSON。

记录当前工程/实际渲染产物标识、格式/时长/非空/削波、逐轨活动、时序问题及覆盖备份。未测连唱和音素边界列为具体未决项，不能写“所有时值对齐通过”。

live Retake 修改编辑器内存，不自动保存。超时可能已执行，先查实际状态，不盲目重试；不要声称离线保存了 live 修改。不同 Studio 实例用不同 session。

需要电平交付时，显式使用 render --target-peak -1 或 audio-normalize；这是采样峰值增益，不是 LUFS 或真峰值归一化。逐轨独立归一化会改变原有声部平衡，只在用户需要时使用。
