# SV2 工程制作

使用 sv2cli 0.2.0 或更新版本。先检查 `sv2cli --version`、`capabilities` 和所需命令的 `--help`；离线编辑不要求开启 Studio，实际合成要求已安装并激活的 VST3 和声库。

## 按任务加载说明

- 音色、声库、语言和保谱编辑：读 [references/edit-and-render.md](references/edit-and-render.md)。
- “时值不对”“没唱齐”、起收音、短字、与参考表演对齐：优先读 [references/timing-and-expression.md](references/timing-and-expression.md)。
- 渲染失败、分轨、交付：读 [references/delivery.md](references/delivery.md)。
- 自动化任务的进度、质量闭环与用户新反馈：读 [references/feedback-loop.md](references/feedback-loop.md)。

## 执行原则

1. 识别实际输入工程、目标轨、改动目标和输出。沿用用户已经表达的授权；不要因需要保存或覆盖而反复确认。只有缺少会改变结果的信息才提问，并继续不依赖答案的工作。
2. 分清三种需求：修正写谱的 onset/duration；修正渲染后实际起收音；对齐参考表演的自由速度/表情。谱面本身正确时，不因发声晚而默认改音符或整曲 BPM。
3. 检查 `inspect`、`validate`，用 `groups` 查看引用 UUID、共享关系、小节与秒数；用 `notes` 核对目标数量。明确选择器，注意 `#N` 为一基轨号、离线组索引从 0 开始、live API 采用一基引用索引。
4. 将要求转成具体 recipe 或命令，检查 `recipe-schema`。预览影响范围并使用合适的 score-lock。未知参数、Vocal Mode 或声库能力从实际工程/官方资料核对，不能凭名称臆造。
5. 按用户选择保存：允许覆盖时用 `--in-place` 或 `-o 原工程 --force`，工具自动备份并原子替换；要求另存时使用新路径。覆盖授权不等于允许改谱；谱面锁定独立生效。不要把历史的“不得覆盖”偏好强加到新任务。
6. 需要音频时先做代表性短工程/已有片段，再完整渲染。当前没有原生 region-render；不要编造该选项。手工制作临时片段时保留正确的变速、组偏移和前滚，声明它是测试副本。
7. 验收分别报告：谱面差异、实际发声活动/时序证据、参考表演对照、主观听审。文件不空、指纹一致或 `valid:true` 均不能替代“唱齐/唱对/像参考”的证据。

自动化优先完成可确定步骤。低置信度音素、连续同音短字、连唱或参考对应关系，标注具体轨/小节/字和需要复核的原因；不要把整曲退回手工处理。

自动执行也要反馈：开始时说明目标与检查依据；在发现、改动、校验、回退等有意义的节点简短更新。将用户的新反馈落实到当前约束和局部验收，再进入“测量—修改—重渲染—复查”的循环。不要长时间沉默，也不要用无变化的状态刷屏。

## 完成标准

用户要求修改工程时应交付实际保存的工程；要求音频时应交付本次生成且读回检查的音频。说明覆盖路径及备份路径（若有）、完成的检查和具体未决项。不要将仅准备好的工程描述为已完成合成，也不要将能量代理描述为精确音素对齐。
